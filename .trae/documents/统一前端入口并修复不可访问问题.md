## 现象与原因
- 日志中的 `GET /@vite/client 404` 表示浏览器在后端端口尝试加载 Vite 开发资源，但后端未运行 Vite 开发服务器，因而 404。
- 当前后端内置的管理页入口为 `GET /ui`，是纯静态页面，不依赖 Vite；如果访问根路径 `/` 会返回 JSON，不会渲染前端。

## 立即可用的操作
- 打开管理页：在浏览器访问 `http://127.0.0.1:8000/ui`。
- 若要使用 React/Vite 开发模式：在 `frontend` 目录执行 `npm i && npm run dev`，然后访问 `http://127.0.0.1:5173`（开发端口），并确保后端已启动用于 API。

## 方案选择（保留一个前端）
- 方案A（推荐）：仅保留后端内置管理页 `/ui`，不启用 Streamlit/Vite。
  1. 将根路径 `/` 重定向到 `/ui`，避免误访问导致 404。
  2. 保留现有功能：模板编辑、LLM开关、训练集预热、上传目录筛选入库、批量决策导出与可视化。
  3. 在页面顶部输入 `Bearer Token`，所有请求自动带鉴权头。
- 方案B：仅保留 React/Vite 前端。
  1. 执行构建：`npm run build` 在 `frontend/dist` 生成产物。
  2. 后端挂载 `frontend/dist` 为 `/ui` 静态目录，替换当前管理页；根路径 `/` 重定向到 `/ui`。
  3. 所有可视化与操作从 React 前端发起，后端继续暴露同一 API。
- 方案C：仅保留 Streamlit（不推荐，扩展性较差），若选择则把现有功能迁移到 Streamlit 页签并关闭管理页。

## 拟实施步骤（按方案A执行）
1. 修改后端根路由，使 `GET /` 重定向到 `/ui`。
2. 在启动日志中输出管理页地址，便于直接点击访问。
3. 验证 `/ui` 的各模块：上传、预热、筛选入库、批量决策与图表渲染均正常，鉴权成功。

## 验证与交付
- 用管理员/HR令牌在 `/ui` 顶部填写后，逐项调用接口并观察成功响应与图表。
- 终端日志不再出现 `/@vite/client 404`（因为入口统一到 `/ui`）。
